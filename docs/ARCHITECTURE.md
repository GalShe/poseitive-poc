# החלטות ארכיטקטורה: טיוטה לאישור M1

> המסמך מתעדכן לפי תוצאות ה-POC (`results/summary.json`, לשונית **תוצאות POC** באתר).
> החלטה שמסומנת **[ממתין לנתונים]** תיסגר אחרי הבדיקה המתאימה.

## תרשים

```mermaid
flowchart LR
  subgraph Phone["מכשיר המטופל (דפדפן / PWA)"]
    CAM[מצלמת RGB] --> POSE["מנוע זיהוי שלד<br/>MediaPipe Pose Lite<br/>(מאחורי ממשק PoseEngine)"]
    POSE --> FEAT["חישוב מדדים<br/>זווית ברך, גו מול שוק"]
    FEAT --> LIVE["משוב מיידי<br/>התרעה על הישענות יתר"]
    FEAT --> REP["סיום חזרה<br/>ספירה + DTW מול ייחוס"]
    REP --> FB["משוב ויזואלי וקולי"]
    REP --> Q[(תור מקומי<br/>אימונים שלא נשלחו)]
  end
  Q -- "מדדים בלבד (JSON)<br/>בלי וידאו" --> API
  subgraph Server["שרת"]
    API["API + הרשאות<br/>מטפל ↔ מטופל"] --> DB[(PostgreSQL<br/>טבלאות + JSONB + מערכים)]
  end
  PT["ממשק פיזיותרפיסט (ווב)"] --> API
  PT -- "הקלטת ייחוס במפגש" --> POSE
```

## ההחלטות

| # | החלטה | חלופות שנבחנו | מבוסס על | מצב |
|---|---|---|---|---|
| 1 | **עיבוד במכשיר**. לשרת נשלחים רק מדדים בסוף האימון | עיבוד בשרת, שילוב | בדיקת ביצועים בטלפונים; עלות העלאת וידאו מול נקודות שלד (`analysis`, test_server_vs_device); פרטיות (סיכון 4) | [ממתין לנתונים] |
| 2 | **MediaPipe Pose Lite**, עטוף בממשק `PoseEngine` | Full, YOLO-Pose | FPS ודיוק לפי תנאי צילום | [ממתין לנתונים] |
| 3 | **אפליקציית ווב (PWA)** עם MediaPipe Tasks for Web | Flutter, React Native, Kotlin | ל-MediaPipe יש תמיכה רשמית בווב ובאנדרואיד ואין לו תמיכה רשמית ב-Flutter/RN; קוד אחד לאייפון ולאנדרואיד; ממשק המטפל ממילא ווב. ווב היא הדרך האיטית ביותר להריץ את המנוע, ולכן אם היא עומדת בקריטריון, נייטיב יעמוד בוודאי | [ממתין לנתונים] |
| 4 | **PostgreSQL**: טבלאות לישויות, `REAL[]` לרצפי זוויות, `JSONB` לספים | MongoDB | `db/benchmark.py`: אותן 5 שאילתות, אותן תשובות; מפתחות זרים כבסיס להרשאות (סיכון 4); היכרות הצוות עם SQL (מגבלה 2) | **הוחלט.** 752,760 חזרות: תשובות זהות בכל 5 השאילתות; PostgreSQL מהיר או שווה למונגו בכולן (Q2, לוח המטפל: 0.97 ms מול 4.3 ms) |
| 5 | **צילום מהצד מזווית קבועה** + בדיקת מיקום לפני אימון (כל המפרקים נראים, visibility ≥ 0.5) | צילום חזיתי | מטריצת תנאי הצילום | [ממתין לנתונים] |
| 6 | **משוב בשתי שכבות**: ספים בזמן התנועה, DTW בסוף חזרה | DTW בלבד, סיווג ML | מאמר [2]; אין מאגר מתויג לאימון מסווג | הוחלט (סקר ספרות) |
| 7 | **ייחוס**: אחת או ממוצע של שלוש הקלטות | | טסט יציבות ייחוס | [ממתין לנתונים] |
| 8 | **תנועת פיצוי ראשונה: הישענות יתר בסקווט** (גו מול שוק). סף 38° (כויל בבדיקה חיה: תקין 16–29°, נשען 49°; מתחיל ב-20° שגרם להתרעות שווא) | | NASM OHSA; טסט זיהוי על סרטוני lean_* | [ממתין לנתונים + אישור פיזיותרפיסט] |
